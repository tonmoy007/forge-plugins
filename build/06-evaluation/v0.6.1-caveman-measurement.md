# v0.6.1 caveman measurement — the gate that dropped the toggle

> **Outcome: DROP the runtime toggle.** The opt-in caveman terse-output preamble showed **no
> reliable output-token saving** on Forge's free-prose dispatches — well under the REQ-CM-005 ≥10%
> bar — so v0.6.1 ships only the deterministic static prompt tightening (T-223/REQ-CM-004). This is
> the measurement gate working as designed: it stopped a token-reduction feature that doesn't reduce
> tokens.

## Method

Representative free-prose dispatch: the **Dreamer consolidation prompt** (`dreamer._CONSOLIDATION_PROMPT`)
— the honest worst case, since it already says *"Terse and concrete. No bullet lists."* and bounds the
answer to *"one short paragraph (3-5 sentences)."*

The same prompt was dispatched through the production chokepoint (`_background_agent.dispatch`,
`claude -p --output-format json`), **N=5** times with the caveman preamble **off** and **N=5** times
with it **on** (`lite`), model `haiku` (as the Dreamer pins). Each run used a fresh temp `.forge`
ledger so cost never gated. The metric is the model's reported `usage.output_tokens` — the exact value
the `_cost_cap` ledger records. `FORGE_CAVEMAN` was unset for the off arm.

Harness: `scratchpad/measure_caveman.py` (one-off; not committed — it makes real paid dispatches).

## Raw data (output tokens)

| Arm | Runs | Mean | Median | Min | Max |
|-----|------|------|--------|-----|-----|
| **OFF** (no preamble) | 555, 647, 721, 761, 422 | **621.2** | 647 | 422 | 761 |
| **ON** (`lite` preamble) | 497, 572, 1676, 612, 1391 | **949.6** | 612 | 497 | 1676 |

**Realized saving (mean): −52.9%** — i.e. the preamble arm produced *more* output on average, not
less. Median-based saving is ≈ +5.4% (647 → 612), still under the 10% bar.

## Interpretation (honest)

- **No reliable saving exists.** The central tendency shows no reduction; the mean is *negative*. A
  generic "answer with maximum brevity" instruction does not shrink output that is **already bounded**
  by the prompt ("3-5 sentences, terse, no bullet lists"). There is no headroom for it to recover.
- **The signal is noise-dominated.** `haiku` ignored the length bound in two ON runs (1676, 1391
  tokens), which inflates the ON mean. Even discarding them, the best-case median saving (~5%) is below
  10%. The variance itself is the finding: the preamble does not *reliably* do anything.
- **This matches the SRS's own prior** (`srs-v0.6.1.md` §1.1): *"Forge's free-prose prompts are already
  terse… the feature must prove its saving, not assert it,"* and caveman's headline ~65% *"does not
  transfer."* It did not.

### Limitations

N=5 per arm is small and LLM output is high-variance, so the precise percentage is not trustworthy.
But the **decision** does not hinge on precision: there is no evidence of a ≥10% reduction in any
reading (mean, median, or best case), which is all the gate needs. More samples would tighten an
estimate that already points the wrong way; they would not produce a ≥10% win that isn't there.

## Decision (REQ-CM-005 gate)

`measured saving < 10%` → **drop the runtime toggle.** Reverted: `caveman_mode`/`caveman_level` config
(T-220), `hooks/_caveman.py` (T-221), and the dispatch-chokepoint + engine wiring (T-222). **Kept:**
the deterministic non-verdict prompt tightening (T-223), which is a real, always-on input-token win
independent of any toggle. Recorded in `decisions.md` and ADR-011.

## Mechanism coverage (was proven before the drop)

The dropped wiring *was* fully tested before reverting — the four-point matrix (free-prose applied ·
schema-constrained skipped · off-identity · never-raises) passed at commit `52bc5d1` (20 tests across
`test_caveman.py`, `test_background_agent.py`, `test_workflow.py`, `test_orchestrate.py`). The mechanism
worked; it simply produced no saving worth shipping. The negative result is the deliverable.
