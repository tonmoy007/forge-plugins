# Sample: TODO API

> This is a fixture project used by `tests/integration/full-pipeline.sh` to run the full
> Forge pipeline end-to-end. **Do not edit the artifacts here manually** — they get
> regenerated by every e2e test run.

## What It Is

A minimal description of a TODO API project that Forge will orchestrate from Stage 1 to Stage 12:

- REST API for managing TODO items
- User authentication
- Postgres persistence
- Deployed as a container

The e2e test:
1. Wipes any existing `pipeline/` and `.forge/` here
2. Runs `claude -p` (headless mode) with scripted prompts that walk through `/forge:init`,
   `/forge:srs`, etc.
3. Asserts each stage produces its expected artifacts
4. Asserts the traceability chain holds (REQ-IDs → FEAT-IDs → Components → Tasks → Tests)

## Initial Project Description

(This is what gets fed to `/forge:srs` in the e2e test.)

> I want to build a TODO API. Users should be able to sign up, log in, and manage their
> own TODO items. Each TODO has a title, optional description, optional due date, and a
> done/not-done status. Users should be able to filter their TODOs by status and due date.
> The API should be deployable as a Docker container and use Postgres for storage.

## Running the E2E Test

```bash
# From the repo root:
bash tests/integration/full-pipeline.sh
```

The test takes ~5–10 minutes as it actually runs Claude through all 12 stages.
For faster iteration, run a single stage:

```bash
bash tests/integration/single-stage.sh --stage 1 --project examples/sample-todo-api
```
